# Exact certified added-leaf relay v1

Independent PR Lean CI remains mandatory. For a same-repository Formal PR that only adds up to 32 MathlibAnalytic Lean leaves, its successful Lean job may publish a small artifact of the new module outputs, with exact PR/test-merge/full Git tree, mathematical tree, pins, run attempt, audited declarations, and per-file SHA-256. No proof statement is weakened.

After an ordinary two-parent merge, a separate read-only trusted Formal job checks the associated PR, independent workflow/job/Lean step and MCP receipt, exact source/test-merge/merged tree and parents, exact artifact origin and archive digest, exact leaf file set and hashes. It restores the exact predecessor full cache from a completed trusted publication, refuses overwrites, overlays only outputs belonging to added leaves, and requires lake build --no-build for the changed modules. Only then may it save the new exact baseline full cache. The proof is the independent PR run, not this relay. The actual Lean push job is skipped only after a successful relay including exact cache visibility. Any missing artifact/cache, pin/tree/parent mismatch, or failed no-build check invokes the existing build on a separate clean runner. Non-leaf and infrastructure changes always retain the old path.

Compact cache publication is manual/optional; full-cache consumers do not wait for it. The existing compact publisher is still limited to exact completed direct Formal push Lean evidence, so a relay-only baseline is not automatically eligible for that optional legacy optimization.

CI receipts distinguish legacy-check-job from certified-pr-relay-no-rebuild. Never label a skipped Lean job as a new proof execution. No existing Lean source, root, pins, strict audit or proof assumption is modified. Cache storage/transfer time is not yet benchmarked. The relay must be validated on a real merged eligible leaf before treating the optimization as established. A relay miss is not a mathematical proof failure.
