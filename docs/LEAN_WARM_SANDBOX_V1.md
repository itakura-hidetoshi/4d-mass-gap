# Exact-source warm Lean sandbox v1

This reusable workflow adopts the byte-identical verifier tested in #6931 (run 45328999333), plus the reusable wrapper and read-only inventory exercised in #6932 (run 45330137137). It does not adopt any diagnostic Lean file or change the canonical Lean root. The latter run correctly failed on AOY candidates despite successful environment restoration; failed candidates did not launch MCP or independent Lean CI.

Call .github/workflows/lean-warm-sandbox-reusable-v1.yml from a diagnostic PR workflow with an exact source_head, certified baseline_commit and diagnostic pack path. The pack binds the original MGAP4D Git tree, three pinned toolchain/manifest/Lakefile blobs, CodeAI pin, imports, per-group candidate blobs and complete public axiom print list. Match all statements/imports between candidates; additionally use the native bounded proof-only patch guard when generating a repair from preceding diagnostics. A new candidate is not authorized merely by a successful preflight. Keep all previous candidates, never merge diagnostic PRs, and only adopt identical green bytes into a separately independently certified research PR.

One runner restores exact toolchain, mathlib and canonical project caches once; validates dependency imports once; tries bounded candidates in distinct scratch files; preserves complete logs; starts one actual lean-lsp-mcp client lazily; requires matching complete direct and MCP axiom audits; stops each group at its first green. Missing cache or incomplete output is HOLD, never a mathematical success. No paid model calls. The verifier executes pre-authored alternatives and native guarded repairs, not autonomous arbitrary theorem changes.

Measured replay: aggregate three old run durations 614 s versus 241 s warm; some old runs overlapped, so this is not a serial wall-clock comparison. Subsequent AOY R3 ran in 7.844 s after R2 in 36.09 s; it still failed warning-as-error. These are observations, not performance guarantees. No setup JSON is removed in this production v1. Cache compaction is a separate experiment; retain trusted caches until independently validated.
